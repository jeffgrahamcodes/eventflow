# EventFlow CLI Specification

**Version:** 1.0
**Status:** Draft
**Sprint:** EF-030

---

## Overview

The `ef` CLI is the developer interface for EventFlow. It provides three
commands that cover the full development lifecycle of an event-driven
consumer: scaffold a new consumer, emit test events, and discover the
event catalog.

```bash
ef init        # scaffold a new event consumer
ef emit        # publish a test event
ef list-events # display all registered event schemas
```

---

## Installation

After cloning the repo and running `uv sync`, the `ef` command is
available on PATH automatically:

```bash
git clone git@github.com:jeffgrahamcodes/eventflow.git
cd eventflow
uv sync --extra dev
ef --help
```

Expected output:

## Commands

### `ef init`

Scaffolds a new event consumer — a Lambda handler, a CDK construct stub,
and a test file — following EventFlow conventions exactly.

#### Signature

```bash
ef init [OPTIONS]
```

#### Options

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `--name` | string | Yes | Consumer name in snake_case (e.g. `fraud_detection`) |
| `--event-type` | string | Yes | Event type to consume (e.g. `order.placed`) |

If `--name` and `--event-type` are omitted, the command runs interactively
and prompts for both.

#### Happy path — interactive

```bash
$ ef init
Consumer name: fraud_detection
Event type: order.placed

Scaffolding fraud_detection consumer...

  Created src/eventflow/handlers/fraud_detection_handler.py
  Created infra/lib/constructs/fraud_detection_construct.ts
  Created tests/test_handlers/test_fraud_detection_handler.py

✓ fraud_detection consumer scaffolded successfully.

Next steps:
  1. Implement the handler in src/eventflow/handlers/fraud_detection_handler.py
  2. Add the construct to infra/lib/eventflow-stack.ts
  3. Run: uv run pytest tests/test_handlers/test_fraud_detection_handler.py
```

#### Happy path — non-interactive

```bash
$ ef init --name fraud_detection --event-type order.placed

Scaffolding fraud_detection consumer...

  Created src/eventflow/handlers/fraud_detection_handler.py
  Created infra/lib/constructs/fraud_detection_construct.ts
  Created tests/test_handlers/test_fraud_detection_handler.py

✓ fraud_detection consumer scaffolded successfully.
```

#### Error — consumer already exists

```bash
$ ef init --name fraud_detection --event-type order.placed

Error: Consumer 'fraud_detection' already exists.
  src/eventflow/handlers/fraud_detection_handler.py already exists.

Use a different name or delete the existing files before reinitialising.
```

#### Error — unknown event type

```bash
$ ef init --name fraud_detection --event-type order.unknown

Error: Unknown event type 'order.unknown'.
  Run 'ef list-events' to see all registered event types.
```

### `ef emit`

Publishes a test event to the local in-memory bus or the deployed AWS
EventBridge bus.

#### Signature

```bash
ef emit --event-type EVENT_TYPE --payload JSON [OPTIONS]
```

#### Options

| Option | Type | Required | Description |
| --- | --- | --- | --- |
| `--event-type` | string | Yes | Event type to emit (e.g. `order.placed`) |
| `--payload` | JSON string | Yes | Event payload as a JSON string |
| `--env` | `local` \| `aws` | No | Target environment. Default: `local` |
| `--bus-name` | string | No | EventBridge bus name. Default: `eventflow-dev-bus` |

#### Happy path — local mode

```bash
$ ef emit --event-type order.placed --payload '{
  "order_id": "abc-123",
  "customer_id": "cust-456",
  "items": [{"sku": "WIDGET-001", "quantity": 2, "price": 24.99}],
  "total_amount": 49.98,
  "shipping_address": "123 Main St, Philadelphia, PA 19103"
}'

Running in local mode...

Event chain:
  → order.placed          (OrderService)
  → order.validated       (OrderService)
  → stock.reserved        (InventoryService)
  → payment.charged       (PaymentService)
  → order.confirmed       (OrderService)
  → customer.notified     (NotificationService)

✓ 6 events emitted. Pipeline completed successfully.
```

#### Happy path — AWS mode

```bash
$ ef emit --event-type order.placed --env aws --payload '{...}'

Publishing to EventBridge bus: eventflow-dev-bus (us-east-1)...

✓ Event published successfully.
  event_type:  order.placed
  event_id:    7f3a2b1c-...
  bus:         eventflow-dev-bus

Run 'uv run python scripts/smoke_test.py' to verify end-to-end.
```

#### Error — unknown event type

```bash
$ ef emit --event-type order.unknown --payload '{}'

Error: Unknown event type 'order.unknown'.
  Run 'ef list-events' to see all registered event types.
```

#### Error — invalid JSON payload

```bash
$ ef emit --event-type order.placed --payload '{invalid json}'

Error: Invalid JSON payload.
  JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```

#### Error — payload validation failure

```bash
$ ef emit --event-type order.placed --payload '{"order_id": "abc"}'

Error: Payload validation failed for 'order.placed'.
  total_amount: Field required
  items: Field required
  customer_id: Field required

Run 'ef list-events order.placed' to see required fields.
```

## Implementation Notes

**Entry point:** `src/eventflow/cli.py`

**Registration in pyproject.toml:**

```toml
[project.scripts]
ef = "eventflow.cli:app"
```

**Framework:** Typer with Rich for table output.

**Event type validation:** All `--event-type` arguments are validated against
the registered event models in `src/eventflow/events/__init__.py`. Unknown
event types produce an error with a reference to `ef list-events`.

**Local mode bus:** Uses `FakeEventBus` from `tests/conftest.py` — all four
services are registered, events are collected, and the full chain is printed
in emission order.

**AWS mode:** Uses `boto3.client("events").put_events()` with
`EVENT_BUS_NAME` from environment or `--bus-name` flag.
